# Classification, extraction, verification: implementation details

## Classification, extraction, text-grounded verification, and reproducibility

Figure classification used category-specific caption inclusion and exclusion dictionaries. An exclusion match took precedence over an inclusion match. Captions matching neither list were rejected. Dictionaries cover anatomy, modalities, and non-radiologic material such as pathology images, diagrams, and charts.

The first extraction pass requested findings, diagnosis, and laterality using category-specific prompts. Inputs comprised the article title, author keywords, the first 1,000 characters of the abstract, up to 2,000 characters of case-presentation text, the figure caption, and figure-referencing text. Case-presentation text was withheld for articles with multiple figures to reduce attribution across figures or patients. Patient age and sex were recovered with text patterns when present in figure-level evidence. Extracted diagnoses were normalized against author keywords and a curated map, followed by Unified Medical Language System (UMLS) concept standardization. 

The default extraction model was Claude Haiku 4.5, followed by Mistral Large 3 and Claude Sonnet 4.6 when required. The primary stage allowed up to three attempts for errors or invalid outputs, with exponential backoff, followed by one middle-tier and one escalation-tier attempt. An invalid extraction after this extraction model fallback triggered a forced Sonnet re-extraction; still-invalid output was excluded. Validation included permissible laterality values and rejection of uninformative findings. Within Verification, the diagnosis–caption consistency check used Haiku and the first 500 caption characters. An explicit diagnosis–caption mismatch triggered one forced Sonnet re-extraction. A case could then be accepted despite a repeated mismatch. The diagnosis–caption consistency check and the independent verifier are reported as one functional Verification component.

A second pass rewrote only the finding using the target caption, sentences citing that figure, and the original finding. Diagnosis and the other first-pass fields were retained. Sentences referring only to other figures were excluded; sentences also citing other figures were marked. Haiku was instructed to preserve only findings stated for the target figure and to keep distinct panels or time points separate when explicitly described. Finding-rewrite fallback retained the original finding if the rewrite was empty, if the proportion of new finding words present in the figure evidence was below 0.5, or if the call failed. The current corpus contains 15,626 cases with a figure-scoped finding and 264 with the original finding retained. The 264 finding-rewrite fallback cases are a different category from the extraction model fallback described above. The independent verifier judged the finding supported in 221 and unclear in 43 of these 264 cases (no figure-scoped finding, 10 and 8; low lexical support, 211 and 35); cases with an unsupported finding were excluded from the corpus.

Amazon Nova Pro then checked the stored text using evidence separated by scope. Figure evidence supported classification, finding, laterality, and depiction judgments. Title, keywords, and up to 2,500 abstract characters were additional context only for the article-level diagnosis judgment. Outputs distinguished supported, unclear, and not supported; absence of a statement was to be labeled unclear rather than contradicted. Diagnosis support in the article was separate from whether its imaging manifestations were depicted in the figure. The verifier also returned diagnostic status, per-condition depiction, and normalized-term equivalence. The verifier processes text and does not inspect image pixels.

Nova Pro was selected following development comparisons with gpt-oss-120b and DeepSeek V3.2. These comparisons and prompt revisions used development material. The final exclusion rule removed 588 cases whose category or finding was labeled not supported by the independent verifier: 421 for category and 167 additional cases for finding. Cases with an unsupported diagnosis status were not excluded by this rule.

`docs/models_and_inference_settings.md` gives the model identifiers and settings. The first extraction pass did not set temperature or top-p explicitly and did not retain per-case attempt counts, token use, or latency. Later rewriting and verifier logs retain model, timestamp, prompt and settings, output, token counts, and duration where recorded.
